# Leave Management API

A Spring Boot REST API that lets employees submit and manage leave requests for an organization's HR system. It is built with a clean layered architecture (Controller → Service → Repository) and stores data in an in-memory `ConcurrentHashMap`, so no database is needed.

## Tech stack

| | |
|---|---|
| Language | Java 17 |
| Framework | Spring Boot 3.3.5 (Web, Validation) |
| Build | Maven |
| Storage | In-memory (`ConcurrentHashMap` + `AtomicLong` id sequence) |
| Testing | JUnit 5, Mockito, AssertJ, MockMvc |

## Project structure

```
src/main/java/com/rsl/leavemanagement
├── LeaveManagementApplication.java     # entry point
├── controller/   LeaveController        # REST endpoints only, no business logic
├── service/      LeaveService           # business rules
├── repository/   LeaveRepository (interface), InMemoryLeaveRepository
├── model/        LeaveRequest, LeaveType, LeaveStatus
├── dto/          LeaveCreateRequest, LeaveUpdateRequest, LeaveResponse, ErrorResponse,
│                 LeaveMapper, @ValidDateRange + DateRangeValidator (custom constraint)
├── exception/    GlobalExceptionHandler (@RestControllerAdvice), LeaveNotFoundException,
│                 InvalidLeaveRequestException, LeaveConflictException
└── config/       LeaveProperties (@ConfigurationProperties), ClockConfig,
                  DevDataInitializer (@Profile("dev")), StartupInfoLogger (@Value)

src/main/resources
├── application.yml        # common config, default profile = dev
├── application-dev.yml    # dev: seeds sample data, DEBUG logs, backdating allowed
└── application-prod.yml   # prod: stricter limits, quieter logs, port from $PORT

src/test/java/com/rsl/leavemanagement
├── service/LeaveServiceTest               # unit tests (Mockito, fixed Clock)
├── controller/LeaveControllerTest         # @WebMvcTest + MockMvc
├── repository/InMemoryLeaveRepositoryTest # repository + concurrency
├── LeaveApiIntegrationTest                # @SpringBootTest end-to-end CRUD flow
└── LeaveManagementApplicationTests        # context loads with the test profile
```

## How the requirements are covered

| Requirement | Where |
|---|---|
| Maven project setup | `pom.xml` |
| Layered architecture | `controller` → `service` → `repository` |
| Constructor-based DI | `LeaveController`, `LeaveService`, `StartupInfoLogger` (no field `@Autowired` in main code) |
| DTOs for requests and responses | `LeaveCreateRequest`, `LeaveUpdateRequest`, `LeaveResponse`, `ErrorResponse` |
| Bean Validation | `@NotBlank`, `@NotNull`, `@Pattern`, `@Size` on DTOs + custom class-level `@ValidDateRange`, triggered by `@Valid` |
| Global exception handling | `GlobalExceptionHandler` (`@RestControllerAdvice`) |
| YAML configuration | `application.yml`, bound through `LeaveProperties` (`@ConfigurationProperties`) and `@Value` |
| Spring profiles | `dev` (default), `prod`, `test`; `DevDataInitializer` is `@Profile("dev")` |
| Service unit tests | `LeaveServiceTest` |
| MockMvc controller tests | `LeaveControllerTest` |

## Data model

| Field | Type | Notes |
|---|---|---|
| `id` | Long | Generated by the server |
| `employeeId` | String | Required, 3–20 letters/digits/hyphens (e.g. `EMP001`) |
| `leaveType` | Enum | `CASUAL`, `SICK`, `EARNED`, `MATERNITY`, `PATERNITY`, `UNPAID` |
| `startDate` | Date | Required, `yyyy-MM-dd` |
| `endDate` | Date | Required, must be on or after `startDate` |
| `reason` | String | Required, 5–500 characters |
| `status` | Enum | `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`. New requests are always `PENDING` |

Responses also include `numberOfDays` (inclusive), `createdAt`, and `updatedAt`.

### Business rules

1. `endDate` must not be before `startDate` → **400**
2. A leave can span at most `app.leave.max-days-per-request` days (30 by default, 20 in `prod`) → **400**
3. A new leave cannot start in the past unless `app.leave.allow-backdated-requests=true` (true in `dev`) → **400**
4. An employee cannot have two active (`PENDING`/`APPROVED`) leaves with overlapping dates → **409**
5. A leave that is `APPROVED`, `REJECTED`, or `CANCELLED` is final and cannot be updated → **409**

## Build and run

**Prerequisites:** JDK 17 or newer, and Maven 3.9+ (or open the project in IntelliJ IDEA, which bundles Maven).

```bash
# Build and run all tests
mvn clean verify

# Run with the default (dev) profile, which seeds 3 sample leave requests
mvn spring-boot:run

# Run with a specific profile
mvn spring-boot:run -Dspring-boot.run.profiles=prod

# Or run the packaged jar
mvn clean package
java -jar target/leave-management-api-0.0.1-SNAPSHOT.jar                      # dev
java -jar target/leave-management-api-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

**In IntelliJ:** open the folder, let Maven import it, and run `LeaveManagementApplication`. To choose a profile, set *Active profiles* in the run configuration.

The app starts on `http://localhost:8080`. When it is ready, you'll see a log line like this:

```
leave-management-api is up on port 8080 | profiles=[dev] | maxDaysPerRequest=30 | allowBackdatedRequests=true
```

## API endpoints

Base URL: `http://localhost:8080`

| Method | Endpoint | Description | Success | Errors |
|---|---|---|---|---|
| GET | `/leaves` | Get all leave requests. Optional filters: `?employeeId=EMP001&status=PENDING` | 200 | 400 (bad `status`) |
| GET | `/leaves/{id}` | Get a leave request by ID | 200 | 404, 400 (non-numeric id) |
| POST | `/leaves` | Create a leave request | 201 + `Location` header | 400, 409 |
| PUT | `/leaves/{id}` | Update a leave request (full replacement, `status` required) | 200 | 400, 404, 409 |
| DELETE | `/leaves/{id}` | Delete a leave request | 204 | 404 |

### Examples

**Create**

```bash
curl -i -X POST http://localhost:8080/leaves \
  -H "Content-Type: application/json" \
  -d '{"employeeId":"EMP010","leaveType":"CASUAL","startDate":"2026-12-21","endDate":"2026-12-23","reason":"Attending sister'"'"'s wedding"}'
```

```json
{
  "id": 4,
  "employeeId": "EMP010",
  "leaveType": "CASUAL",
  "startDate": "2026-12-21",
  "endDate": "2026-12-23",
  "numberOfDays": 3,
  "reason": "Attending sister's wedding",
  "status": "PENDING",
  "createdAt": "2026-09-28T16:45:12.123",
  "updatedAt": "2026-09-28T16:45:12.123"
}
```

**Update (approve)**

```bash
curl -X PUT http://localhost:8080/leaves/4 -H "Content-Type: application/json" \
  -d '{"employeeId":"EMP010","leaveType":"CASUAL","startDate":"2026-12-21","endDate":"2026-12-23","reason":"Attending sister wedding","status":"APPROVED"}'
```

**Get / delete**

```bash
curl http://localhost:8080/leaves
curl http://localhost:8080/leaves/4
curl -i -X DELETE http://localhost:8080/leaves/4
```

On Windows PowerShell, use `curl.exe` instead of `curl`, or use the ready-made requests in **`requests.http`**, which you can run from IntelliJ's HTTP client or import into Postman.

### Error response format

Every error returns the same structure:

```json
{
  "timestamp": "2026-09-28T16:50:03.412",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/leaves",
  "errors": [
    { "field": "employeeId", "message": "employeeId is required" },
    { "field": "endDate", "message": "endDate must be on or after startDate" }
  ]
}
```

`errors` appears only for validation failures. Unexpected errors return 500 with a generic message, and the stack trace is only written to the server log.

## Configuration

| Property | Default | dev | prod | Purpose |
|---|---|---|---|---|
| `server.port` | 8080 | 8080 | `${PORT:8080}` | HTTP port |
| `app.leave.max-days-per-request` | 30 | 30 | 20 | Max days in one request |
| `app.leave.allow-backdated-requests` | false | true | false | Allow a start date in the past |

You can override any property from the command line, for example: `--app.leave.max-days-per-request=15`.

## Testing

```bash
mvn test                                   # run the whole suite
mvn test -Dtest=LeaveServiceTest           # service unit tests only
mvn test -Dtest=LeaveControllerTest        # MockMvc controller tests only
```

In IntelliJ, right-click `src/test/java` and choose **Run 'All Tests'**.

| Test class | Type | What it covers |
|---|---|---|
| `LeaveServiceTest` | Unit (Mockito) | CRUD logic, not-found, date range, max days, backdating on/off, overlap detection, finalized-status guard, no mutation on failure |
| `LeaveControllerTest` | `@WebMvcTest` + MockMvc | Status codes, JSON payloads, `Location` header, validation errors, bad enum/date/JSON, 404/405/409/415/500 handling |
| `InMemoryLeaveRepositoryTest` | Unit | ID generation, replace, filters, delete, concurrent saves |
| `LeaveApiIntegrationTest` | `@SpringBootTest` + MockMvc | Full create → read → update → delete flow through every layer |
| `LeaveManagementApplicationTests` | `@SpringBootTest` | Context loads, `test` profile properties bound, dev-only beans absent |
